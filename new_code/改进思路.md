# 综合代码改造思路与详细执行计划

## 一、 核心改造思路的深度融合

本次改造将从“业务逻辑拟真”、“博弈动力学重构”、“MARL算法调优”和“工程基建”四个维度进行深度融合：

1. **环境动力学与匹配机制（学术亮点+业务拟真）**：
* 摒弃随机盲匹配，引入**基于运筹学的带权二分图匹配（KM算法）**，权重结合订单即时收益与Critic网络的未来价值预估。
* 精细化异质性司机（全职/兼职）的上下线逻辑，引入最低收入阈值和动态意愿。


2. **状态感知与动作干预（解决收敛痛点）**：
* 引入**动作掩码（Action Masking）**，直接在Actor输出端屏蔽“撞墙”等非法移动，消除算力浪费。
* 状态特征升维：用**“空间感知场（Flattened Neighbors）”**替代简单的均值降维，同时补充区域供需比（SD）平滑值、司机历史收益增速等高价值特征。


3. **奖励重塑与PPO内核优化（算法提效）**：
* 奖励函数引入**局部同侪基准（Peer Baseline / Regret）**，将绝对收益转化为相对博弈优势。
* PPO经验池实施**双重掩码（Double Masking）**：不仅过滤离线状态，更要在GAE计算中彻底阻断离线期间的MDP链，防止优势值泄露；同时引入动态熵系数与自适应Clip。


4. **工程架构与评估体系（可复现性与鲁棒性）**：
* 核心逻辑向量化操作替代低效 `for` 循环，缓存六边形邻接表，大幅提升仿真速度。
* 建立多维度评估指标体系（留存率、基尼系数、空间供需平衡度），并通过CSV日志和全方位图表固化实验结果。

## 二、 详细分阶段改造计划

| **1.1 全局最优二分图匹配** | 1. 废弃随机派单。收集意向司机与可用订单，构建二分图。<br>

<br>2. **权重计算**：`Weight = (1-抽成)*溢价*基础费 - 燃油费 + γ*Critic(终点状态)`。<br>

<br>3. 调用 `scipy.optimize.linear_sum_assignment` 实现稳定匹配。 | `ride_hailing_env.py` 的 `step` 函数（重构接单逻辑） | **学术亮点**：将运筹学匹配嵌入RL；解决Critic评估由于随机性导致的剧烈震荡。 |
| **1.2 动作掩码 (Action Masking)** | 1. 新增 `_get_action_mask()`，返回 `[N_DRIVERS, ACTION_DIM]` 布尔矩阵。<br>

<br>2. 屏蔽网格边界外的非法移动，屏蔽无订单时的接单动作。<br>

<br>3. 在PPO的Actor网络中注入掩码，非法动作概率置为0（或 logits 设为 -1e9）。 | `ride_hailing_env.py` 及 `shared_ppo.py` 的 `act` 函数 | **收敛提效**：彻底消除“撞墙”等无效探索，MARL收敛速度预计提升2-3倍。 |

| **1.4 供需比与溢价鲁棒性** | 1. SD计算引入 EMA（指数移动平均），平滑瞬时波动。<br>
